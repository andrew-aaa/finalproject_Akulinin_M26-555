# ValutaTrade Hub

Учебный проект — платформа для отслеживания и симуляции торговли валютами.

## Возможности

* регистрация иавторизация пользователей;
* управление портфелем — просмотр валютных кошельков и общей стоимости портфеля;
* покупка и продажа валюты с проверкой корректности суммы и доступного баланса;
* получение курса обмена между валютами;
* обработка ошибок с понятными сообщениями в CLI;
* кэширование курсов с ограниченным временем действия;
* логирование операций и ошибок с помощью декораторов;
* хранение данных в JSON-файлах;
* гибкая конфигурация с использованием SettingsLoader.

## Технологии

Проект написан на Python 3.12+.

Используются:

* Python;
* `json` для хранения данных;
* `hashlib` для хеширования паролей;
* `datetime` для работы с датами и временем;
* `shlex` для разбора командной строки;
* `prettytable` для вывода портфеля в табличном виде;
* `uv` для управления проектом и зависимостями.

## Запуск

Запустить приложение можно командой:

```bash
uv run python main.py
```

Или:

```bash
uv run valutatrade
```

При запуске появляется приглашение для ввода команд:

```text
ValutaTrade Hub. Введите 'help' для списка команд.
>
```

## Доступные команды

| Команда | Назначение |
|---|---|
| `help` | Показать список доступных команд |
| `register --username <имя> --password <пароль>` | Зарегистрировать пользователя |
| `login --username <имя> --password <пароль>` | Войти в систему |
| `show-portfolio` | Показать валютный портфель |
| `show-portfolio --base EUR` | Показать портфель с оценкой в EUR |
| `buy --currency BTC --amount 0.01` | Купить указанное количество валюты |
| `sell --currency BTC --amount 0.01` | Продать указанное количество валюты |
| `get-rate --from BTC --to USD` | Получить курс одной валюты к другой |
| `exit` | Завершить работу приложения |

Примеры с `BTC`, `EUR` и `USD` приведены для иллюстрации синтаксиса. Доступность конкретной валюты зависит от её наличия в модели валют проекта.

## Архитектура

Проект разделён на несколько уровней:

- **`cli`** отвечает за ввод команд, разбор аргументов и отображение результатов.
- **`core`** содержит модели предметной области, бизнес-логику и пользовательские исключения.
- **`infra`** отвечает за доступ к данным и загрузку конфигурации.
- **`decorators.py`** содержит декораторы для журналирования операций.
- **`logging_config.py`** настраивает систему логирования.
- **`main.py`** запускает приложение.

Такое разделение помогает отделить интерфейс пользователя от бизнес-логики и хранения данных.

## Основные технические решения

### Модели валют

Для представления валют используется иерархия классов, позволяющая описывать общие свойства валют и их специализированные варианты.

### Пользовательские исключения

Для ошибок предметной области предусмотрены собственные исключения, включая ситуации, когда валюта не найдена, запрос курса не удался или на кошельке недостаточно средств.

### Singleton

Паттерн Singleton используется в менеджере базы данных и загрузчике настроек, чтобы обеспечить единый экземпляр соответствующего объекта в рамках процесса приложения.

### Логирование

Операции приложения журналируются с использованием декораторов. Настройка логирования вынесена в отдельный модуль; для записи логов используется файловый обработчик с ротацией.

### Хранение данных

Для хранения данных применяется JSON. Доступ к файлам централизован в инфраструктурном слое, что упрощает работу с данными и отделяет её от бизнес-логики.

### Кэширование курсов

Полученные курсы сохраняются в кэше с ограниченным сроком действия. Это позволяет повторно использовать актуальные значения в течение заданного времени.

## Обработка ошибок

Приложение обрабатывает ошибки пользовательского ввода и операции с валютами. В частности, предусмотрены ситуации:

- некорректные или отсутствующие аргументы команды;
- попытка использовать неизвестную валюту;
- недостаточный баланс для продажи или покупки;
- ошибка получения курса обмена;
- попытка выполнить операцию, для которой требуется авторизация.

При возникновении ошибки CLI выводит сообщение, а приложение продолжает работу, если ошибка обработана на уровне интерфейса.
