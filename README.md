# ValutaTrade Hub

Учебный проект — платформа для отслеживания и симуляции торговли валютами.

## Возможности

* регистрация и авторизация пользователей;
* управление портфелем — просмотр валютных кошельков и общей стоимости портфеля;
* покупка и продажа валюты с проверкой корректности суммы и доступного баланса;
* получение курса обмена между валютами;
* получение актуальных курсов криптовалют из CoinGecko;
* получение курсов фиатных валют из ExchangeRate-API;
* ручное обновление курсов из выбранного источника или всех источников;
* локальное кэширование курсов с ограниченным сроком действия;
* хранение текущих курсов и истории обновлений в JSON-файлах;
* обработка ошибок с понятными сообщениями в CLI;
* логирование операций и ошибок;
* настройка приложения через SettingsLoader и конфигурационные файлы.

## Технологии

Проект написан на Python 3.12+.

Используются:

* Python;
* `json` для хранения данных;
* `hashlib` для хеширования паролей;
* `datetime` для работы с датами и временем;
* `shlex` для разбора командной строки;
* `requests` для HTTP-запросов к внешним API;
* `python-dotenv` для загрузки переменных окружения из .env;
* `prettytable` для вывода портфеля в табличном виде;
* `uv` для управления проектом и зависимостями;
* `ruff` для проверки стиля и форматирования кода.

## Настройка API-ключа

Для получения фиатных курсов используется ExchangeRate-API. Ключ задаётся через переменную окружения EXCHANGERATE_API_KEY.

Создайте файл .env в корне проекта:
```bash
EXCHANGERATE_API_KEY=ваш_api_ключ
```

CoinGecko используется для получения курсов криптовалют. Отдельный ключ в текущей конфигурации не задаётся.

## Запуск

Запустить приложение можно командой:

```bash
uv run python main.py
```

Или:

```bash
uv run valutatrade
```

При запуске появляется приглашение для ввода команд:

```text
ValutaTrade Hub. Введите 'help' для списка команд.
>
```

## Доступные команды

| Команда | Назначение |
|---|---|
| `help` | Показать список доступных команд |
| `register --username <имя> --password <пароль>` | Зарегистрировать пользователя |
| `login --username <имя> --password <пароль>` | Войти в систему |
| `show-portfolio` | Показать валютный портфель |
| `show-portfolio --base EUR` | Показать портфель с оценкой в EUR |
| `buy --currency BTC --amount 0.01` | Купить указанное количество валюты |
| `sell --currency BTC --amount 0.01` | Продать указанное количество валюты |
| `get-rate --from BTC --to USD` | Получить курс одной валюты к другой |
| `update-rates` | Обновить курсы из всех настроенных источников |
| `update-rates --source coingecko` | Обновить курсы криптовалют |
| `update-rates --source exchangerate` | Обновить курсы фиатных валют |
| `show-rates` | Показать актуальные курсы из локального кэша |
| `show-rates --currency BTC` | Показать курсы выбранной валюты |
| `show-rates --top 2` | Показать заданное количество курсов |
| `show-rates --base EUR` | Показать курсы относительно EUR |
| `exit` | Завершить работу приложения |

Набор доступных валют определяется конфигурацией и моделями проекта.

### Пример работы

Сначала зарегистрируйте пользователя:

```text
register --username alice --password secret123
```

Затем выполните вход:

```text
login --username alice --password secret123
```

Посмотрите портфель:

```text
show-portfolio
show-portfolio --base EUR
```

Получите курс обмена:

```text
get-rate --from EUR --to USD
```

Покупка и продажа валюты:

```text
buy --currency BTC --amount 0.01
sell --currency EUR --amount 5
```

При продаже валюты приложение списывает указанное количество с соответствующего кошелька и зачисляет выручку в базовой валюте согласно логике приложения.

### Обновление курсов

```text
update-rates
```

Пример сообщения:

```text
Обновление завершено. Сохранено курсов: 6
Время обновления: 2026-10-14T16:42:02Z
```

Обновление можно ограничить одним источником:

```text
update-rates --source coingecko
update-rates --source exchangerate
```

### Просмотр курсов

```text
show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --base EUR
```

Команда show-rates использует локальный кэш. Устаревшие значения отфильтровываются с учётом настройки rate_cache_ttl.

## Хранение данных

Приложение использует JSON-файлы:

* `data/users.json` — зарегистрированные пользователи.
* `data/portfolios.json` — портфели и валютные кошельки.
* `data/rates.json` — текущий кэш курсов.
* `data/exchange_rates.json` — история измерений курсов.

Сервис парсинга сохраняет курсы вместе с источником и временной меткой. Запись JSON выполняется через временный файл с последующей заменой целевого файла.

## Конфигурация

Основные параметры приложения задаются в config.json. Например:

```text
{
    "base_currency": "USD",
    "users_file": "data/users.json",
    "rates_file": "data/rates.json",
    "portfolios_file": "data/portfolios.json",
    "logs_dir": "logs",
    "log_level": "INFO",
    "log_format": "%(asctime)s - %(levelname)s - %(message)s",
    "rate_cache_ttl": 300
}
```

Параметр rate_cache_ttl определяет время актуальности кэша в секундах. Значение 300 соответствует пяти минутам.

Настройки сервиса парсинга находятся в valutatrade_hub/parser_service/config.py. В частности, там задаются базовая валюта, поддерживаемые валюты, URL API, тайм-аут запроса и пути к файлам курсов.

## Архитектура

Проект разделён на несколько уровней:

- **`cli`** отвечает за ввод команд, разбор аргументов и отображение результатов.
- **`core`** содержит модели предметной области, бизнес-логику и пользовательские исключения.
- **`infra`** отвечает за доступ к данным и загрузку конфигурации.
- **`parser_service`**  — получение курсов из внешних API, обновление кэша и запись истории.
- **`decorators.py`** содержит декораторы для журналирования операций.
- **`logging_config.py`** настраивает систему логирования.
- **`main.py`** запускает приложение.

Такое разделение помогает отделить интерфейс пользователя от бизнес-логики и хранения данных.

## Обработка ошибок

Приложение обрабатывает ошибки пользовательского ввода и бизнес-операций, включая:

- некорректные или отсутствующие аргументы команды;
- неизвестную валюту;
- недостаточный баланс;
- отсутствие авторизации для защищённых операций;
- ошибки внешних API;
- некорректный JSON или неожиданный формат ответа.

При ошибке одного источника обновление может продолжиться для другого источника. Сообщения об ошибках и предупреждения выводятся в CLI и журналируются.
